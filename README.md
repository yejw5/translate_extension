# 对照翻译 · Bilingual Translate

基于大模型的 Chrome 整页对照翻译扩展。点一下页面右下角的悬浮按钮，整页英文就会被逐段翻译成中文，**原文段落和译文段落上下对照显示**，原文不会被替换掉。

模型服务完全由你自己配置：服务端地址、API Key、模型名称都可以在设置页填写，支持 OpenAI 兼容协议（DeepSeek、通义千问、智谱、Kimi、硅基流动、OpenRouter、Ollama 等）、Anthropic Claude 和 Google Gemini。

---

## 功能特性

- **常驻入口**：网页右下角悬浮按钮，一键翻译 / 一键恢复原文；鼠标悬停展开语言切换面板
- **对照展示**：译文作为块级元素插入到原段落下方，支持 4 种样式（左侧竖线 / 无装饰 / 虚线分隔 / 浅色卡片）
- **保留超链接**：译文里的链接、行内代码会还原成真正的 `<a>`/`<code>`，沿用原页面的 `href` 和 class，所以和原文一样可点击、一样高亮；行内数学公式（MathJax / KaTeX）整体克隆到译文里
- **字体风格跟随原文**：译文自动继承原段落实际的字号、颜色、透明度、字体，注释类小字不会被渲染成正文大小
- **自带后端配置**：服务端、密钥、模型自选；内置 10 个服务商预设，一键填好地址和默认模型
- **多语言**：18 种语言任意组合，默认 `英语 → 简体中文`
- **智能跳过**：代码块、`<pre>`、纯数字、隐藏元素、以及已经是目标语言的段落都不翻译
- **按视口优先**：先翻译你当前看到的内容，再往下翻译
- **并发 + 分批**：多段落合并成一次请求，多请求并发，速度和 token 消耗都可调
- **译文缓存**：同一段文字不会重复付费
- **动态内容**：无限滚动页面新加载的段落自动翻译
- **密钥不出本机**：API Key 存在 `chrome.storage.local`，请求由 Service Worker 发出，页面脚本接触不到密钥

## 安装

本扩展未上架应用商店，使用开发者模式加载即可。

1. 下载 / 克隆本仓库到本地任意目录。
2. 打开 Chrome，地址栏输入 `chrome://extensions/`。
3. 打开右上角的 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择本项目的根目录（包含 `manifest.json` 的那一层）。
5. 安装完成后会自动打开设置页；也可以在扩展图标上右键 →「选项」进入。

> 要求 Chrome 102+（基于 Manifest V3）。Edge、Brave 等 Chromium 内核浏览器同样适用。

## 配置

首次使用必须填写三项：**服务端地址**、**模型名称**、**API Key**。

在设置页的「服务商预设」里选一个，地址和模型会自动填好，只需粘贴自己的 Key：

| 预设 | 默认模型 | 密钥获取 |
| --- | --- | --- |
| OpenAI | `gpt-4o-mini` | platform.openai.com |
| DeepSeek 深度求索 | `deepseek-chat` | platform.deepseek.com |
| 阿里云百炼 / 通义千问 | `qwen-plus` | bailian.console.aliyun.com |
| 智谱 GLM | `glm-4-flash` | open.bigmodel.cn |
| 月之暗面 Kimi | `moonshot-v1-8k` | platform.moonshot.cn |
| SiliconFlow 硅基流动 | `Qwen/Qwen2.5-7B-Instruct` | cloud.siliconflow.cn |
| OpenRouter | `google/gemini-2.0-flash-001` | openrouter.ai |
| Anthropic Claude | `claude-3-5-haiku-latest` | console.anthropic.com |
| Google Gemini | `gemini-2.0-flash` | aistudio.google.com |
| Ollama 本地模型 | `qwen2.5:7b` | 无需密钥 |
| 自定义 | — | — |

任何兼容 OpenAI `/chat/completions` 协议的服务都可以用「自定义」填入。地址只填到 `/v1` 甚至域名根路径也可以，会自动补全成 `/v1/chat/completions`。

填完点 **测试连接**，会真实调用一次模型翻译 “Hello, world!”，显示耗时和译文即为配置成功。最后点 **保存设置**。

主要设置项：

| 分组 | 设置 | 说明 |
| --- | --- | --- |
| 语言 | 原文语言 / 译文语言 | 默认 英语 → 简体中文；原文可设为「自动检测」 |
| 语言 | 额外要求 | 追加到提示词的自定义指令，可写术语表、语气、行业风格 |
| 展示 | 对照样式 | 译文的视觉区分方式 |
| 展示 | 保留超链接与行内代码 | 默认开启；译文里的链接可点击且高亮与原文一致。模型较弱、经常破坏格式时可以关掉 |
| 展示 | 悬浮按钮位置 / 是否显示 | 四个角可选，也可以完全隐藏只用快捷键 |
| 展示 | 自动翻译域名 | 每行一个域名，打开即自动翻译 |
| 性能 | 并发请求 / 每批段落数 / 每批字符数 | 调大更快，但更易触发限流（429）；调小更稳 |
| 性能 | 温度 / 超时 / 重试次数 | 温度建议 0~0.3 |
| 性能 | 最短翻译长度 | 过滤掉零散的按钮、标签文字 |
| 性能 | 译文缓存 | 可查看占用并一键清空 |

## 使用方式

共有四个入口，效果相同：

1. **页面悬浮按钮**（主要入口）：右下角蓝色「译」按钮
   - 点击 → 开始翻译，按钮变成进度百分比；再点一次可中断
   - 翻译完成后按钮变成绿色「原」→ 点击恢复原文
   - 鼠标悬停 → 展开面板，可临时切换原文/译文语言、查看进度与错误、跳转设置
2. **工具栏图标**：点击扩展图标，在弹窗里选语言并「翻译本页」/「恢复原文」
3. **快捷键**：`Alt+T` 翻译 / 恢复原文（可在 `chrome://extensions/shortcuts` 修改）
4. **右键菜单**：页面任意处右键 →「对照翻译：翻译本页 / 恢复原文」

翻译结果形如：

```
The first thing to notice about a translation layer is that it changes how you read.
│ 关于翻译层，首先要注意的是它改变了你的阅读方式。
```

想试效果可以打开仓库里的 `demo/sample.html`（file:// 页面需要先在 `chrome://extensions/` 里为本扩展勾选「允许访问文件网址」）。

### 翻译其他语言

- 临时切换：悬浮面板或工具栏弹窗里的两个下拉框，改完点「翻译本页」
- 永久修改默认值：设置页 →「语言」分组
- 支持：简体中文、繁體中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、意大利语、阿拉伯语、印地语、泰语、越南语、印尼语、土耳其语（原文语言还可选「自动检测」）

例如要把中文网页译成日语：原文选「简体中文」，译文选「日语」。

## 工作原理

```
content.js  ──扫描 DOM，提取段落，按字符数/段落数分批
     │        （跳过 script/style/pre/code、隐藏元素、已是目标语言的段落）
     ▼  chrome.runtime.sendMessage
background.js ──查缓存 → 未命中的拼成一次请求 → 调用大模型 → 写缓存
     │
     ▼
content.js  ──把译文作为 <span class="bt-translation"> 插到原段落末尾
```

- 提示词要求模型按 `<t id="N">译文</t>` 的格式逐条返回，解析时按 id 对齐，避免段落错位；解析失败会自动重试，仍失败则保留原文并在该段下方显示错误原因。
- 段落里的 `<br>` 会转成真正的换行一起送给模型，提示词要求「原文几行、译文几行」，渲染时再还原成 `<br>`，所以多行注解块不会被压成一整行。
- 超链接、行内代码等元素在送翻前会被包成 `<k0>…</k0>` 这样的编号标记，渲染时按编号克隆原始元素（沿用 `href`、class，去掉 `id`），因此译文里的链接可点击、高亮与原文一致；模型若丢了标记，该段自动退化成纯文本，不会出现残留标记。
- 模型若把 `<item id="N">…</item>` 之类的包裹标签、代码围栏或 HTML 实体一起吐回来，解析和渲染两道都会清掉，页面上不会出现标签。
- 429 / 5xx / 网络错误会按指数退避重试（默认 2 次）。
- 译文用块级 `<span>` 而不是 `<div>` 插入，避免破坏 `<p>`、`<li>`、`<td>` 等原有 HTML 结构。

## 隐私与安全

- API Key 保存在 `chrome.storage.local`（仅本机，不随 Chrome 账号同步），其他设置保存在 `chrome.storage.sync`。
- 所有模型请求由 Service Worker 发出，密钥不会注入到网页上下文，页面 JS 无法读取。
- 被翻译的网页文本会发送到**你自己配置的那个模型服务**，不经过任何第三方服务器。请确认该服务商的数据政策；处理敏感内网页面时建议改用 Ollama 等本地模型。
- 扩展声明了 `<all_urls>` host 权限，这是整页翻译任意网站所必需的。

## 项目结构

```
manifest.json            扩展清单（MV3）
src/
  background.js          Service Worker：模型请求代理、缓存、快捷键、右键菜单
  content.js             段落提取、对照渲染、悬浮按钮（Shadow DOM）
  content.css            译文样式与 4 种对照风格
  popup.html/.css/.js    工具栏弹窗
  options.html/.css/.js  设置页
  lib/
    config.js            设置默认值与读写
    langs.js             语言列表
    providers.js         服务商预设
    translator.js        提示词构造、三种协议适配、译文解析、重试
    cache.js             译文缓存（FIFO 淘汰，上限 3000 条）
icons/                   图标
demo/sample.html         测试页面
test/                    单元测试（node:test，无需安装依赖）
```

## 常见问题

**点了没反应 / 面板提示失败**
悬停悬浮按钮查看面板底部的错误信息，或在设置页点「测试连接」。最常见的是密钥错误、模型名写错、余额不足。

**提示 429 或 rate limit**
把「并发请求」降到 1~2，或把「每批段落数」调大（请求次数更少）。

**提示 CORS / Failed to fetch**
请求是从 Service Worker 发出的，正常不受 CORS 限制。若仍失败，检查地址是否可从本机访问（企业代理、Ollama 未启动等）。Ollama 需要监听 `127.0.0.1:11434` 并已 `ollama pull` 对应模型。

**某些页面上扩展完全不工作**
`chrome://`、Chrome 应用商店、其他扩展页面禁止注入脚本，这是浏览器限制。`file://` 页面需要手动勾选「允许访问文件网址」。

**译文错位或丢段**
说明模型没遵守输出格式。换更强的模型，或把「每批段落数」调小（比如 3~4），单段请求最稳。

**翻译没覆盖全部内容**
短于「最短翻译长度」的文本、代码块、以及被判定为已是目标语言的段落会被跳过。嵌套很深的自定义组件（Shadow DOM 内部）目前不处理。

**费用大概多少**
一篇 2000 词的英文文章约消耗 4k~6k tokens。用 `deepseek-chat`、`glm-4-flash`、`gpt-4o-mini` 这类便宜模型，单篇成本在一分钱量级；相同内容再次翻译会命中缓存，不再计费。

## 已知限制

- 不翻译 iframe 内的内容（`all_frames: false`）和 Shadow DOM 内部文本
- 不翻译页面标题、`alt`/`title`/`placeholder` 等属性文本
- 不支持划词翻译（当前只做整页对照）
- 不使用流式输出，每批译文一次性返回
